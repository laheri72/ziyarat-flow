## 2024-05-17 - N+1 Issue Avoidance and Fetch Optimization
**Learning:** Found multiple instances where we are using `while (true)` loops to fetch all items from `beneficiaries` and `assignments` just to find the set difference between the two to find unassigned beneficiaries. This scales extremely poorly. We are pulling potentially 10,000s to 100,000s of rows into frontend memory just to run an array filter instead of pushing this to the database, or at minimum, keeping things isolated by avoiding full table scans.
**Action:** Replace `while (true)` fetching of ALL records with targeted queries or edge function calls, but since I can only optimize frontend code right now, I should look to see if this can be solved using an `is(null)` or similar query optimization. However, Supabase doesn't easily support left joins with filtering on the null side from the frontend client. Wait, there's a memory rule explicitly addressing this: "To resolve N+1 query bottlenecks with Supabase, extract the specific foreign keys (e.g., student IDs), chunk them into batches of 500, and fetch the related records using an `in` filter. Avoid querying entire tables without filters (`while(true)` loops using `range()`) to prevent scalability regressions and excessive memory usage."
