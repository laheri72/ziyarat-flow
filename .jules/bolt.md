## 2024-05-18 - [Fix N+1 bottleneck on Assignment Fetch]
**Learning:** Performing a full table scan on large relation tables without filters using while(true) loops causes excessive memory usage and slow performance, creating an N+1 query bottleneck. However, when replacing this with chunked `.in()` queries, you must STILL paginate the chunked requests, because Supabase's 1000-row limit applies to the *response payload size*, not just the array filter size.
**Action:** Extract specific foreign keys, chunk them into batches (e.g., 50 to limit the query filter size), and fetch related records using an `in` filter INSIDE a `while(true)` loop with `.range()` pagination to safely retrieve all related records without hitting the 1000-row response truncation. Count items locally using a Map. Avoid querying entire tables without filters.
