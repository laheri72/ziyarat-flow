## 2025-02-18 - Memoizing Filter/Sort and Hoisting String Ops
**Learning:** In React components rendering lists (like in `Admin.tsx` and `Dashboard.tsx`), calculating derived state involving array filtering and sorting on every render is a common performance bottleneck. Furthermore, performing synchronous string operations like `toLowerCase()` inside the inner loop of `filter()` callbacks redundantly allocates memory and blocks the main thread.
**Action:** Always wrap expensive list transformations (filter, map, reduce, sort) in `React.useMemo` to prevent unnecessary recalculations on re-renders when dependencies (like the list itself or search queries) haven't changed. Crucially, hoist static derived values (e.g. `const query = searchQuery ? searchQuery.toLowerCase() : ''`) outside the inner loop callbacks. When sorting with `Array.prototype.sort()` within a useMemo, always apply it to a shallow copy (e.g. `[...arr].sort()`) or ensure it's operating on a freshly created array (like the output of `.filter()`) to avoid mutating React state in place.
